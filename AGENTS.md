## AI Skill OS

Skills for this project are installed in `.agents/skills/` (Agent Skills format). Load a skill's SKILL.md when its description matches the task.

Project rules:
- Project knowledge lives in `.ai/knowledge/`. Search it before scanning the whole codebase (`ai-skills knowledge search <terms>`; `ai-skills knowledge graph <name>` shows what a component, endpoint or table is connected to, with file:line evidence).
- Knowledge and the graph are an index, not the truth. When they disagree, trust in this order: source code, tests, schemas, contracts, requirements, ADRs, documentation, the knowledge index, then inference. Verify against source code for correctness-critical work. Mark anything you infer as INFERRED, never CONFIRMED.
- Claim "done", "fixed" or "passing" only with evidence from this session: run the command that proves it, read its whole output, and quote the result. Report what was not run as NOT RUN.
- Deterministic guards run from `.ai/hooks/` (git pre-commit, and natively where the tool supports hooks). If one blocks you, fix the cause; never bypass it with --no-verify or by weakening lint, type-check, test or CI configuration.
- Before adding code, stop at the first rung that holds: is it needed at all; is it already in this codebase; does the standard library, the platform or an installed dependency do it; only then write the least new code that stays clear. No abstraction, option or layer for a need nobody has yet.
- Each ticket gets its own branch with the ticket ID in its name, created before its first change: from the ticket it depends on while that one is unmerged, otherwise from the base branch. Before building or committing a ticket, check the current branch is that ticket's; if it is not, stop and ask the user. Skip this only when the user has said not to use branches.
- Skill versions are pinned in `.ai/lock.yaml`. Do not edit installed skills in place.

## Plane (this repo's notes, outside the managed block)

Tickets are mirrored in Plane: workspace `drivnx`, project DRIVN (<https://app.plane.so/drivnx/>). The files in
`.ai/knowledge/` stay the source of truth.

- A ticket's ID is its Plane key: `.ai/knowledge/work/DRIVN-31.md` has `id: DRIVN-31` and `external_key: DRIVN-31`.
  Older tickets keep their pre-Plane ID in `legacy_id` (e.g. `CFX-APP-csv-profile-T11`); search for both.
- Features and criteria keep their CFX IDs (`CFX-APP-csv-profile`, `CFX-APP-csv-profile/AC-35`); the feature file's
  `external_key` holds its Plane item (`DRIVN-9`). Tests keep naming criteria by the CFX feature ID.
- Branch `feat/drivn-31-<short-title>`; commit title `DRIVN-31: <description>`; trailers `Spec: <feature ID>`,
  `Ticket: DRIVN-31`, `Criteria: …`.
- When the Plane MCP server is connected: cutting a ticket creates its Plane item first (child of the feature's item,
  label `drivnx-web`, `external_source: drivnx-repo`, `external_id` = the ticket ID) and names the file after the key
  it gets. When a ticket's `state` changes, move the Plane item to match: `ready` → Todo, being built → In Progress,
  `done` → Done, `blocked` → Backlog. Add the PR link to the item when the PR opens. If the MCP server isn't
  connected, say the Plane update is NOT RUN; don't skip it silently.
- Ask before deleting Plane items or changing anything outside project DRIVN.
