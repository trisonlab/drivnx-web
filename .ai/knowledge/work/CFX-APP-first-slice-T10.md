# Full journey and project checks

## Outcome
The whole journey passes against the installed wheel, the CI configuration exists, every check also runs locally, and the performance and accessibility targets are measured.

## Acceptance checklist
- [ ] AC-51 (US-09): Given a built wheel, when it is installed with `uv tool install`, then the `conflux` command serves the bundled UI and API from one origin, and AC-01 passes against it.
- [ ] AC-53 (US-09): Given the repo, then CI configuration runs pytest, Vitest, Playwright, secret scanning and dependency vulnerability checks. Each of those also runs locally with a documented command.
- [ ] AC-54 (US-09): Given `testdata/`, then every file is synthetic and generated by a committed script or documented as hand-written.

## Expected evidence
Playwright journey against the wheel. Measured figures for the 1 GB CSV, an automated accessibility check, and a final spike 6 run. CI, macOS and Windows reported as NOT RUN until they can run.

## From the T01 review
- `uv build --wheel` succeeds with a missing or outdated UI bundle, and the wheel ships without it or with the old one. Reproduced in the T01 review. Provide one build command that builds the UI first and checks the result, and test it.
- The wheel declares `fastapi>=` and `uvicorn>=`, so `uv tool install` and the test install can pick versions newer than `uv.lock`. Choose how released versions are pinned (Section 7 of the direction doc), and make the test install match it.

## From the T02 review
- Some integration tests are POSIX-only: `os.killpg`, `send_signal(SIGINT)` and the shell-script browser stand-ins. Make them portable or mark them before running CI on Windows. On macOS, `webbrowser` finds browsers differently, so check that the tests still can't open a real one.
