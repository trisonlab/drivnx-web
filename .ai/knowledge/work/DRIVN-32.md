# Full journey and checks

## Outcome
The whole journey passes against the installed wheel, a scan for planted values proves the R3 rule, the new screens pass the accessibility check, and the targets are measured.

## Acceptance checklist
- [x] AC-33 (US-06): Given a full journey with distinctive planted values in a synthetic file, including on-request values, then a raw scan of `workspace.db` and its WAL finds no value from the file, except masked patterns and column names, and logs at their most detailed hold none either.
- [x] AC-40 (US-08): Given `testdata/`, then each new file is synthetic and generated by a committed script or documented as hand-written.
- [x] AC-41 (US-08): Given the installed wheel, then the journey of connecting a CSV, correcting it, running a fast profile, running a full profile and opening a finding's evidence passes in Playwright from one origin, with an automated accessibility check on the new screens in each state.

## Expected evidence
Playwright against the wheel, a raw scan of `workspace.db` and its WAL file, logs at their most detailed, measured figures for the 1 GB CSV, and an automated accessibility check. The CI run on Ubuntu, macOS and Windows for the pull request.

## Plan agreed with the user
Decided by the user, 2026-11-12, taking every recommendation:
- **One new file, `tests/e2e/test_profile_journey.py`,** started with `--no-browser`, so unlike `test_full_journey.py` it isn't `posix_only` and runs on Windows too. `journey_csv(path) -> list[str]` writes a synthetic file in `tmp_path` and returns every distinct value in it. The file has a title line above a tab-separated table, so it needs correcting. It has `id`, `email` (possibly sensitive), `city` (a quarter missing), `amount` (one value that doesn't fit its type) and a repeated last row, over 3,000 rows. Every value is distinctive: `zq{n}k@planted.example`, invented city names, and 11-digit amounts. `walk_the_profile_journey(page, path, at_each_state)` goes from connect, through the correction, a fast profile, a flagged column's values after confirming, and a full profile with findings, to a finding's evidence.
- **AC-41:** the journey from one origin, with `violations(page) == []` in each state, plus axe checks in `test_accessibility.py` on the states the journey skips: running with Cancel, cancelled, couldn't finish, settings that can't read the file, an earlier run opened after a correction, nothing to point out, and interrupted when DrivnX stopped (restarted on the same workspace).
- **AC-33:** the journey under `--log-level trace`. **Every file in the workspace folder,** not only `workspace.db` and its WAL, so DuckDB spill files left behind are caught too. It scans while DrivnX runs, while the WAL is still there, and again after it stops, as well as everything DrivnX printed. A second test fails a full profile on a quote that's never closed, next to a planted value, in case DuckDB's error quotes the line. Masked patterns must be found, so a scan that reads nothing can't pass, and the scan is shown to catch a planted value before it's trusted.
- **AC-40:** already proven by `test_testdata.py`. Nothing new goes in `testdata/`.
- **Targets:** `tests/measure_large_csv.py` also times a fast profile, a full profile and a cancel 2 s into a full run through the UI, on 1 GB on the NVMe disk with the page cache dropped, for UTF-8 and Latin-1, twice each. A miss is reported, not redesigned.
- **A leak AC-33 finds** stops the build and goes to the user before any product code changes.

## What building it showed
- **The journey file changed from the plan.** `id` is `rq{n}vz`, as plain numbers from 1 to 3,000 aren't distinctive enough to scan for. It has no mistyped `amount` and no repeated row: one finding is enough to open its evidence, and "city is missing" gives it.
- **A failed full profile's alert reads "This profile couldn't finish. A row in this file can't be read, …".** "This profile couldn't finish, so it has no results." shows only when there's no reason to give.
- **The "couldn't finish" axe check sits in the AC-33 test of a failed full profile,** as `test_accessibility.py` importing from `test_profile_journey.py` would be a circular import. `test_values.py` already mixes its criteria with axe checks the same way.
- **The lock file is checked to be empty, not read.** It's never written, and on Windows its first byte is locked while DrivnX runs.
- **No value was found in the workspace or the logs.** Uvicorn's trace lines hide bodies and headers and print paths and query strings, which hold only column names today. A failed full profile fails through DrivnX's own check with its own message. Whether DuckDB's error text would quote the line is INFERRED, not seen.
- **Every new test was seen failing when what it checks was broken:** the journey without the correction, an image without alt text in the page or in `violations()` (all 7 axe checks failed at their first assertion), and a planted value as the workspace name and in a logged URL (the scans caught both).
- **`measure_large_csv.py` resolves its directory,** as DrivnX refuses a relative path to a file.

## From the review
- **The AC-33 scans could pass by reading nothing.** The failed-profile test took its workspace folder from the fixture's naming, and a folder that didn't exist scanned as empty. Both AC-33 tests now name their workspace, and a scan fails unless `workspace.db` is there.
- **A value saved only in part would have been missed,** as the scan looked for whole values. It now matches any part that could tell someone what a value was (`zq…k`, `rq…vz`, the numbers' first seven digits, the invented names and the email domain), and checks that every planted value matches before trusting a clean result. Masked patterns can't match. Seen catching a workspace named "Quillmarsh team".
- **The journey also asks for a number column's values,** whose histogram, mean and median are worked out on request too, with an axe check in that state.
- New lines are wrapped at 99 characters, as the files around them are.
