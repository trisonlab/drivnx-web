# Threat register — Phase 1

The one-page register required by the direction doc (§7, §12). **Only the first row and the connected-database row
have code and tests in full; the input limits row is built and tested for CSV and PostgreSQL, R3 for both, the key leaks
row for PostgreSQL passwords and values but not exports or API keys, and the other mitigations are still planned.** Update a row when its test ships. The product claims in §7 stay off-limits until then.

## Threats

| Threat | Mitigation | Decided in | Status |
|---|---|---|---|
| Malicious web page calls the local API | Loopback binding; exact Host and Origin checks; per-launch token in an `HttpOnly` cookie; GET routes have no side effects; a Content-Security-Policy stops other pages framing the UI | §7, ADR 0001 | Implemented and tested (T02). First spike 6 pass 2026-11-01, Chromium only |
| Database or API key leaks | OS credential store; masking; never in SQLite, URLs, browser storage, logs or exports | §7, ADRs 0004, 0007 and 0008 | Implemented and tested for PostgreSQL passwords (`DRIVN-45`, DRIVN-47 and DRIVN-48): kept in the OS credential store (Keychain, Credential Manager or Secret Service, through keyring; on Windows on this computer only) where there is one, else in memory until DrivnX stops, and given to DuckDB only as a temporary secret, never in the connection string or DuckDB's errors. AC-30's browser test plants a password the server refuses, one stored and refused after a restart, and the right one, and finds no part of any in the workspace's files, the logs at trace level, browser storage or a URL the browser requested. Implemented and tested for a database's values (`DRIVN-45` AC-12, AC-28, AC-29, ADR 0004): a profile saves only counts, percentages, text lengths and masked patterns, and a preview and values on request are read when asked, sent with `Cache-Control: no-store` and never saved; the full journey's scan (DRIVN-58) finds no planted value in the workspace while DrivnX runs and after it stops, or in its logs at trace level. Planned: exports, which don't exist yet, and API keys, with AI (M8) |
| DrivnX changes a connected database | Read-only sessions; no writes; bounded queries; cancellation | §7, ADR 0007 | Read-only sessions implemented and tested (DRIVN-47, `DRIVN-45` AC-14): DuckDB attaches read-only and the server starts every transaction read-only, and a write through either alone is refused by the server. Bounded queries and cancellation implemented and tested (DRIVN-53, AC-20 to AC-22, ADR 0009): every statement has a server-side `statement_timeout`, 30 s by default and on a full profile the per-object time limit (1 to 120 minutes) plus 30 s, and a per-object timer stops a full read at its limit. A cancel or a limit interrupts DuckDB, and if the read hasn't returned within 1 s a second connection sends `pg_cancel_backend` for the job's session and closes; tests check `pg_stat_activity` has no DrivnX query left running within 5 s, for a table, a view and a fast reading. A session ended or a privilege revoked mid-read fails the run with the object and the reason. The full journey's statement log tested (DRIVN-58, AC-15): with the server logging every statement of a role that may write one of the chosen objects, every one DrivnX sent carries `application_name` `DrivnX` and is a read, and a write sent through DrivnX's session fails the test by name |
| Sensitive data sent to AI unintentionally | AI off by default; context preview; explicit approval; audit record | §6, §7 | Planned (M8) |
| Workspace copied or stolen | Owner-only permissions; no credentials in the workspace; raw data not copied by default | §7, ADR 0002 | Planned; see R3 and R4 |
| Huge or malformed input exhausts resources | Sampling; size warnings; limits; cancellation | §5, §7 | Implemented and tested for CSV (`DRIVN-9`): a fast profile reads only the first 100,000 rows, a full profile runs only on request and cancels within 5 s (AC-10), and a file over 100 MB in an encoding that must be decoded in memory is refused (AC-03). No size warnings yet, and the number of columns isn't capped. Implemented and tested for PostgreSQL (`DRIVN-45`): a fast profile samples about 100,000 rows of a table and reads a view's first rows (DRIVN-51, ADR 0005), and a full profile runs only on request, each object within its time limit, and cancels within 5 s (DRIVN-53). Planned for XLSX and Parquet (M2) |
| AI produces incorrect documentation | Inferred state; human review | §3, §12 | Planned (M1, M8) |

## Residual risks

| # | Risk | Position | Owner of next step |
|---|---|---|---|
| R1 | **The session cookie reaches other local servers.** Cookies aren't isolated by port, so any server on `127.0.0.1` receives it for paths under `/api` and could replay it. **Confirmed in spike 6** (Chromium, 2026-11-01, and again against the installed wheel on 2026-11-05): a server on another port received the token, and replaying it passed sign-in. The cookie did not reach paths outside `/api`. The same server can also overwrite the cookie, which signs the user out until they restart DrivnX, because the launch code is already used (reproduced in Chromium, T02 review). The launch URL is also passed to the browser as a command-line argument, so other local users may briefly be able to see it; it is single-use, and no attack on this was attempted. | Accepted for Phase 1: a program running as the same user can already read the workspace. Weakest on shared machines. | Revisit at hardening (M9) |
| R2 | **Windows permissions.** No ACL code in Phase 1. Owner-only access relies on the workspace being under the user's profile, which is the default location. | Accepted for Phase 1 (ADR 0002). | Revisit at hardening (M9) |
| R3 | **Values taken from source data are stored in the workspace:** min/max, frequent values, pattern examples, dictionary examples, contract accepted values, a row of a CSV that detection used as column names because it couldn't tell a header from data (AC-22), and their backups and SQLite free pages. This conflicts with "raw data not copied by default". | **Rule built and tested for CSV profiling (ADR 0004, `DRIVN-9` AC-04 and AC-33), and for PostgreSQL (`DRIVN-45` AC-29, ADR 0005 Decision 4).** A profile saves only counts, percentages, text lengths and masked patterns, and values are computed on request and never saved; a database's preview and values are read from it again when asked. **Still open:** a row used as column names that the user never corrects stays saved, and the screen says so; pre-migration backups can keep names replaced later; dictionary examples and contract accepted values aren't covered. | Dictionary and contract slices for what's left |
| R4 | **DuckDB spill files can hold source data** for the length of a job, or until the next start after a crash. They stay inside the workspace (ADR 0002 point 7). | Accepted for Phase 1. The setting is in place and tested (AC-49). | None |
| R5 | **Workspaces in sync folders or on network drives.** A sync service could copy the live database, and WAL isn't safe on network filesystems. The runtime warns about known sync folders. Network filesystems aren't detected. | Accepted for Phase 1 (ADR 0002). | Document for users |
